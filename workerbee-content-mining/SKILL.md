# 工蜂内容线：博主与机会挖掘

前置：`workerbee-connect` 拿地址钥匙。本 skill 是**内容线**（看互动找机会），
跟 `workerbee-selection` 的**商品线**（看销量找爆品）互补，两条线可以并行跑。

## 三种典型诉求，三条路

| 用户想要 | 走哪条路 |
|---|---|
| 「谁在卖这个品？」 | 路 A：矩阵号猎手（挂车反查） |
| 「这个品类的博主怎么发笔记？」 | 路 B：博主发现 → 深采代表作 |
| 「有哪些需求火了但没人变现？」 | 路 C：海选 → 筛无挂车高互动 → 取证 |

## 路 A：矩阵号猎手（挂车反查）

顺着一个店铺，反查所有在带它货的账号：

```json
POST /api/local/tasks/advanced
{"task_type":"matrix_creator_discovery","keywords":["品类词1","品类词2"],
 "target_seller_id":"<商家ID>","note_limit_per_keyword":30,"max_scrolls":10}
```

结果里 `matched_creators` 是命中的矩阵号，`evidence_notes` 是逐条挂车证据。

**先判断这条路适不适用**——它靠"笔记里挂商品卡"反查：

- ✅ 适用：实物品类，博主普遍带购物车
- ❌ 不适用：**虚拟品**（测评链接、资料包、课程），多数靠店铺直销，笔记根本不挂车
  > 实案：某测评品类扫了 24 篇笔记，只有 3 篇挂车、0 命中。改走路 B/C 才有产出。

先小规模试（1-2 个词、每词 10 篇），命中率太低就立刻换路，别硬扫。

0 命中返回 `completed` + `no_matrix_match`——**只说明本轮没发现，不能断言"这家店没有矩阵号"**。

## 路 B：博主发现 → 拆笔记打法

```json
POST /api/local/tasks/advanced
{"task_type":"creator_discovery","keywords":["品类词"],"note_limit_per_keyword":30,"max_scrolls":10}
```

拿到 `notes[].user_id` 后，**先按互动量筛，再决定采谁**：

### 互动冷热门槛（省额度的关键）

算个热度分：`赞 + 藏×2 + 评×5`（评论权重最高，因为评论是最重的互动）。

- **互动冷的博主直接跳过，不要采**。一个赞几十的博主没有拆解价值。
- 每个值得研究的博主取 **3-5 篇**代表作即可，不用全采。

然后对选中的笔记发深采任务（`note_link`，直接把笔记链接丢给 `/api/local/tasks/batch`），
拿到标题/正文/话题标签/封面/挂车情况。

### 拆什么

汇报时要给出**可复用的规律**，不是流水账：

- **标题句式**：如「测测你前世是…」「30S测出你的…」「N道题：…」
- **正文结构**：常见套路是"先剧透 3 条结果勾人 → 再说只要几道题降低门槛"
- **话题标签策略**：几个大流量通用标签 + 一个垂直标签
- **怎么挂车/怎么引流**：挂商品卡、还是引导评论区、还是引导私信

## 路 C：找「已验证需求但没变现」的机会（最有价值）

### 判据

一篇笔记同时满足这两条，就是机会：

1. **互动极高**（尤其评论数）→ 需求被验证了
2. **没有挂车** → 博主没在这上面赚钱

### 做法

**第 1 步：海选**。大范围扫笔记，拿到标题/作者/互动数。这一步要广不要深。

先问一句「**你有 root 过的安卓手机吗？**」——有就用 `root_keyword_search`（秒级、产量高、
不占普通手机），没有就用 `creator_discovery`（普通手机，慢些但结果一样能用）。
多数人没有 root 机，**别因此说做不了**。

**第 2 步：粗筛**。按互动阈值留候选（比如评论 ≥ 一定量或热度分靠前），每个博主只取最热的 1 篇，
避免同一个人刷屏。

> ⚠️ **无标题卡片是雷区（2026-08-07 实案）**：搜索接口返回的卡片里会混进推荐流内容，
> 而且这类卡片**常常没有标题、没有作者**——你只看得到互动数，看不到它是什么。
> 实测一批「AI工作台」搜索结果里，6 张无标题卡有 5 张是车祸围观、明星八卦、怀旧内容，
> 只有 1 张真是目标内容（而且恰恰是全场最强的一篇）。
>
> **规矩：无标题/无作者的卡片，在深采确认内容之前，不许进任何统计口径、不许写进给用户的榜单。**
> 正确顺序是「先深采确认 → 再算榜」，不是「先算榜 → 事后纠正」。
> 深采后用标题/正文/话题标签判定相关性，**判定用的关键词要足够具体**——
> 用 `ai` 这种两字母词会把 `#AIGC` 的无关明星笔记也匹配进来（同一实案踩过）。

**第 3 步：验挂车**。对候选笔记发 `note_link` 深采任务，看结果里 `goods_cards` 是否为空。
**空的才是机会**，有挂车的留作对照组（它证明这个方向能赚钱）。

**第 4 步：取证与定级**。看评论数量级定机会等级，结合对照组里的同类商品定价，
给出「改造成什么产品、定价多少」的建议。

### 汇报要点

对照组非常重要——**"有人已经把同类需求做成商品并卖出 N 单"** 是这个机会值得做的最硬证据。
把机会笔记和对照商品放在一起给用户看。

## 导出

- 博主笔记打法 → `workerbee-feishu-delivery`，`template=note`
- 机会清单 → `template=opportunity`（额外带机会方向/产品形态/MVP形态/机会等级/下一步动作等列）

## 诚实边界

- **评论内容**：工蜂的任务结果里有**评论数**，但不含评论正文。判断"评论区反馈热烈"时，
  评论数是可靠的量化指标；想看用户具体在说什么，给用户笔记直达链接让他自己点进去看，
  **不要编造评论内容**。
- **搜索结果会掺沙子**：卡片流里混着推荐内容，无标题卡尤其可疑（见上方雷区）。
  报数前先确认这些条目到底是什么，**别把无关热帖的互动量算进目标赛道的热度**——
  一旦算进去，你给用户的"这个赛道很火"就是假的。
- **未命中 ≠ 不存在**：任何一轮扫描的 0 结果都只代表本轮本词没发现。
- **别把冷数据说成热的**：互动量低就如实说这个方向没起来。
