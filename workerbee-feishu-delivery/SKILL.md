# 工蜂 → 飞书多维表格交付

前置：拿到工蜂接口的 `base_url` 和钥匙（用户从工蜂 设置 → 接口开放 复制「给 AI 的说明」粘给你，或读 discovery 文件 `<appData>/工蜂/api.json`；接口说明书在 `GET /api/docs`）。下文 `$BASE`/`$KEY` 指代它们。

## 铁律：走这一个端点，不要自己拼字段

```bash
curl -s -X POST "$BASE/api/feishu/export" \
  -H "X-Api-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"task_ids":[101,102],"template":"goods"}'
```

工蜂服务端会自动完成：建表 → 建齐所有字段 → 按模板填值 → **下载图片传成附件** →
多选标签写完回读校验 → 把表格所有权移交给用户。返回 `{ok,url,count,failed_count,attachment_count}`。

**为什么必须走它**：模板是产品契约。曾经有 AI 自己拼字段写表，结果字段少一半、图片只写了
会过期的链接、标签写成纯文本没法筛选——用户拿到的是个残表。你直接调飞书开放平台 API
自己建表拼字段，就是在重蹈覆辙。

## 三个模板怎么选

| template | 用于 | 表里有什么 |
|---|---|---|
| `goods` | 商品类任务（关键词搜索/商品链接/店铺） | 28 字段：标题·价格·销量·**卖点标签(多选)**·**主图/详情图/视频附件**·店铺名称·粉丝·评分·口碑·销量·文本链接·商品ID·店铺ID·物流信息 |
| `note` | 笔记类任务（笔记链接/号主主页/博主发现/矩阵猎手/root搜索） | 22 字段：标题·文本链接·作者·号主ID·主页文本链接·类型·赞·藏·评·分享·发布时间·正文·**笔记标签(多选)**·封面链接+**封面附件**·图片·视频链接·挂车商品·挂车商家ID·来源词·采集状态 |
| `opportunity` | 「未变现机会」清单 | 笔记模板 + 机会挖掘列：机会方向·产品形态·用户购买的结果·MVP形态·自动化比例·人工介入程度·机会等级·合规风险·下一步动作·评论区实况·备注 |

选错了会得到明确报错（`NO_RECORDS` = 这批任务没商品，该用 note；`NO_NOTES` = 没笔记，该用 goods）。

## 字段口径与分表规则

这些规则适用于所有工蜂结果表，包括服务端已有模板和用户明确要求补写的评论、店铺档案、主页信息等补充表：

- **按结果结构分 sheet，不按来源分 sheet**。关键词商品、单个商品、店铺商品都进同一张「商品」表；单篇笔记、博主主页笔记、博主发现笔记都进同一张「笔记」表。来源差异需要保留时，用「来源类型」「来源任务」等字段表达，不要拆成多个来源 sheet。
- sheet 名优先用中文业务名，例如「商品」「笔记」「店铺档案」「商品评价」「博主主页」「笔记评论」。不要用 `01_keyword` 这类只有任务来源的名字交付给用户。
- 链接一律建成**文本字段**，不要使用飞书 URL 字段类型。商品链接、店铺链接、笔记链接、主页链接、图片链接、视频链接都按文本写入；图片/封面/视频能传附件时仍按模板传附件。
- 类数字字段要转成数字字段，不要同时保留「原文文本」副本。例如 `2.6万` 写成 `26000`，`1,234` 写成 `1234`。
- 确定是计数/整数的字段，用整数展示格式：销量、粉丝数、点赞数、收藏数、评论数、分享数、重复次数、任务 ID、图片数、监控天数等。
- 可能有小数的字段继续用小数格式：价格、评分、好评率、日销售额、自动化比例等。
- `/api/feishu/export` 暂不支持的结果类型，不要静默自由发挥。先告诉用户默认端点支持哪些模板，再和用户确认字段；用户明确同意后，补充表也必须遵守上面的字段口径。

## 参数

| 参数 | 说明 |
|---|---|
| `task_ids` | 必填，任务号数组，一次最多 50 个 |
| `template` | `goods` / `note` / `opportunity`，默认 `goods` |
| `base_url` | 留空=**新建**一张多维表格；填已有表格链接=写进那张表 |
| `table_name` | 表内数据表名，默认按模板给（商品数据/笔记数据/机会笔记） |
| `base_name` | 新建表格的名字，默认「工蜂采集结果 + 时间」 |
| `upload_attachments` | 默认 `true`，**不要随便关** |
| `extra_fields` | 仅 `opportunity` 模板：把你的分析判断写进机会列，见下节 |

## 把你的分析写进机会表（opportunity 专用）

`opportunity` 模板会建出机会分析列，但工蜂只填得了客观数据（笔记内容/互动数），
**主观判断要你给**。通过 `extra_fields` 传，按 task_id 分组：

```json
{
  "task_ids": [101, 102],
  "template": "opportunity",
  "extra_fields": {
    "101": {
      "机会方向": "前世神仙测试",
      "产品形态": "自动化测评网页（答题→即时出结果页）",
      "用户购买的结果": "个性化测评结果报告",
      "MVP形态": "H5 测题页 + 结果图，店铺挂虚拟商品自动发货",
      "自动化比例": 100,
      "人工介入程度": "无（当前博主靠评论区人工回复，正是痛点）",
      "机会等级": "A",
      "合规风险": "娱乐向测评，避免医疗/心理诊断表述",
      "下一步动作": "复刻概念做 H5，定价 ¥2.99-4.99",
      "评论区实况": "评论区大量用户提交答案序列等回复",
      "备注": "对照组：同类已售 1.2 万单"
    }
  }
}
```

可用列名只有这 11 个：机会方向 / 产品形态 / 用户购买的结果 / MVP形态 / 自动化比例 /
人工介入程度 / 机会等级 / 合规风险 / 下一步动作 / 评论区实况 / 备注。
**传别的列名会被丢弃**——想要新列请让用户在飞书表格里自己加。

## 为什么默认要传附件

小红书图床链接**带时效签名，会过期**。只存链接的表格过一阵子就全是死图。
所以默认把图片下载成附件存进表格。代价是慢一些（每张图要下载+上传）。

只有当用户明确说"快速导出就行 / 不要图片"时才传 `upload_attachments: false`，
并且要告诉用户这个取舍。

## 多张表放进同一个表格

第一次调用不传 `base_url`，拿到返回的 `url`；后续调用把这个 `url` 传进去 + 换 `table_name`，
就会在同一个多维表格里加新的数据表。

```
第1次：{"task_ids":[101],"template":"goods","table_name":"爆卖商品"}        → 得到 url
第2次：{"task_ids":[102],"template":"note","table_name":"博主笔记","base_url":"<url>"}
第3次：{"task_ids":[103],"template":"opportunity","table_name":"机会清单","base_url":"<url>"}
```

## 前置条件

用户需先在工蜂**设置页配置飞书应用凭证**（企业自建应用的 App ID / App Secret，
并开通多维表格权限），否则返回 `FEISHU_NOT_CONFIGURED`。
设置里还可以填用户姓名，表格建好后会自动移交到用户名下、进「我的空间」。

## 用户想要不一样的表怎么办

模板是**默认值不是牢笼**：

- 想加列：让用户在飞书表格里直接加，下次写入不会删掉用户加的列。
- 想改口径/改字段：先如实告诉用户"默认模板是什么样、为什么这样设计"，用户坚持要改的，
  可以在写完后由用户自行调整，或你按用户明确的要求补充说明。
- **不要因为自己觉得字段太多就擅自精简**——完整字段是有人踩过坑才定下来的。

## 汇报给用户

导出完成后告诉用户：表格链接、写入条数、传了多少附件、归属是否已移交。
`failed_count > 0` 时如实说明有几条没写进去和原因，不要只报成功数。
